## What is Git

Git is a **distributed version control system** designed to track, manage, and organize changes made to files—especially source code—throughout the life of a software project. Instead of having to manually create copies of a project such as `project-final`, `project-final-2`, `project-final-REAL`, and `project-final-USE-THIS-ONE`.

### **Benefits of Git**

Git maintains a structured history of your work. You can save a snapshot of your project using 
- A **commit**, inspect exactly what changed, compare different versions, undo mistakes, and return to an earlier state when necessary.

- **branches**, which are separate lines of development where they can experiment with new features, fix bugs, or completely change part of an application without disturbing the main version. Once the work is ready, branches can be merged back together. Because Git is distributed, every developer working with a repository can have a complete copy of its history, rather than relying entirely on one central machine. 

This makes Git extremely useful not only for recovering from mistakes, but also for experimenting fearlessly: you can try something:

1. ambitious
2. break everything
3. understand what happened
4. Restore the project to a known working state.

Git becomes even more powerful when it is used for:

### **collaboration and professional software development**. 

Multiple developers can work on different parts of the same project, create *branches* for their tasks, *commit* their changes, and eventually *merge* those changes together. Git records who made changes, when they were made, and what was changed, creating an auditable history of the project. When two developers modify the same part of a file, Git can identify the **conflict**, allowing the developers to decide which changes should remain or how the two versions should be combined. 

Git itself is the version-control technology; platforms such as **GitHub, GitLab, and Bitbucket** build on top of Git by providing:

1. Online repositories
2. Collaboration tools
3. Pull requests
4. Code reviews
5. Issue tracking
6. Automated workflows and other development features. 

In practice, Git becomes the backbone of a developer's workflow: 
- you **clone** a project, 
- make changes, **stage** them, 
- **commit** them with meaningful descriptions, 
- **push** them to a remote repository, 
- **pull** other people's changes, 
- create **branches** for new work, and **merge** completed work back together.

- HTML

**HTML(HyperText Markup Language)** is the standard language used to build and structure web pages on the internet. It is not a programming language; instead, it uses tags to define elements like text, images, links, and forms.

**Basic Anatomy of HTML**

HTML elements are enclosed in angle brackets (< >). Most elements have an opening tag, content, and a closing tag.

**Example:**

>"&lt;p&gt;Welcome to my website&lt;p&gt;"

A complete HTML page follows a standard layout:

    <!DOCTYPE html>
        <html>
        <head>
             <title>Page Title</title>
        </head>
    <body>
    <h1>Main Heading</h1>
    <p>This is a paragraph.</p>
    <a href="https://example.com">This is a link</a>
    </body>
    </html>

# Common Core Tags

**1. &lt;h1&gt; to &lt;h6&gt;-** *Headings (from largest to smallest).*

**2. &lt;p&gt; -**  *Paragragh text.*

**3. &lt;a&gt; -** *Hyperlinks to other pages or sections.*

**4. &lt;img&gt; -** *Embeds images.*

**5. &lt;div&gt; -** *Generic container used to group content.*

# Conclusion

HTML provides the essential backbone for any webpage by structuring content with tags like headings, paragraphs, links, and containers. While CSS adds visual styling and JavaScript provides interactivity, HTML remains the foundational building block of the modern web.
